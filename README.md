### 🧠 الملاحظات الهندسية والمفاهيم المعمارية (Engineering Notes)
1. **لماذا حولنا `Shipment` من `Struct` إلى `Class` بينما أبقينا `DeliveryAddress` كـ `Struct`؟**
   - `Shipment` هو كيان ذو هوية (`Entity`) يمر بدورة حياة، يدعم **الوراثة (`Inheritance`)** و**تعدد الأشكال (`Polymorphism`)**، وتمريره عبر المرجع (`Reference Pointer`) يمنع نسخ بيانات ضخمة على الـ Stack. بينما `DeliveryAddress` هو `Value Object` صغير وثابت الهوية.
2. **شجرة الوراثة وتسلسل البناء (`Constructor Chaining via : base(...)`):**
   - الفئة الأب `Shipment` تحتوي على البيانات المشتركة والدوال الافتراضية (`virtual EstimatedCost` و `virtual PrintShipment()`).
   - الفئات المشتقة (`StandardShipment`, `ExpressShipment`, `InternationalShipment`) تستدعي باني الأب عبر `: base(trackingCode, description, weight, deliveryFee, destination)` لضمان تهيئة جزء الأب في الذاكرة أولاً قبل تهيئة الحقول الخاصة بالابن (`ExtraFee`, `DestinationCountry`, `CustomsFee`).

## 🗂️ هيكلة الكود والتمارين التطبيقية المحلولة

| المكون | الدور المعماري | التفاصيل المطبقة في الكود |
| :--- | :--- | :--- |
| **Part 01** | Theoretical Analysis (Q1 & Q2) | الفرق المعماري بين `Class` و `Struct`، وتطبيق مبدأ `DRY` عبر الوراثة. |
| **`Shipment`** | Base Reference Class | الفئة الأساسية للشحنات مع `virtual decimal EstimatedCost` و `virtual void PrintShipment()`. |
| **`StandardShipment`** | Derived Class | شحنة قياسية ترث من `Shipment` وتمرر المعاملات لباني الأب `: base(...)`. |
| **`ExpressShipment`** | Derived Class | تضيف `ExtraFee` وتعيد تعريف حساب التكلفة `override decimal EstimatedCost`. |
| **`InternationalShipment`** | Derived Class | تضيف `DestinationCountry` و `CustomsFee` وتدمج الرسوم الجمركية في `EstimatedCost`. |
| **`DeliveryCenter`** | Polymorphic Container | تخزن جميع أنواع الشحنات المشتقة داخل مصفوفة موحدة `Shipment[]` بفضل الـ Upcasting. |
